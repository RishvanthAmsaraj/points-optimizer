# Testing Walkthrough

Exact steps to verify the app end-to-end in mock mode (no external API keys), with expected outcomes. The mock provider is **deterministic** — the same route + date + cabin always returns the same award space — so these scenarios are reproducible. Numbers below were generated by `npx tsx scripts/scenario-check.ts`, which runs the same data through the real provider and engine; run it any time to re-verify without touching the browser.

## One-time setup

1. `.env.local`: copy from `.env.example`, fill in your Supabase URL + anon key + service-role key. Leave `AWARD_PROVIDER=mock`. **Set `PLAYBOOK_FREE_LIMIT=999`** so the free-tier cap doesn't interrupt testing (put it back to 2 before launch).
2. Apply migrations **001 → 002 → 003** in the Supabase SQL editor (or `supabase db push`).
3. Seed reference data: `npx tsx scripts/seed-programs.ts` then `npx tsx scripts/seed-transfer-rates.ts` then `npx tsx scripts/seed-cards.ts`. Every line should print ✓ — a "program not found" warning means step order was wrong.
4. `npm run dev`, open http://localhost:3000, create an account on /login. (If Supabase email confirmation is on, confirm via the email; for local testing it's easiest to turn confirmation off in Supabase Auth settings.)
5. Sanity: the landing page CTAs go to /login; after sign-in the nav shows Dashboard / Points / Cards / Playbook; Dashboard shows the "Log your first balance" empty state.

## Scenario A — the flagship playbook

**Add balances (Points page):** Chase Ultimate Rewards `200000`, Marriott Bonvoy `20000`.
**Cards page:** add Chase Sapphire Preferred (any open date).
**Playbook:** JFK → NRT, departure `2026-10-14`, no return, Business, 1 passenger.

Expected:
- Best route: **Chase Ultimate Rewards → Air Canada Aeroplan — 97,000 pts, 3.47¢/pt**, steps: transfer 97,000 Chase → Aeroplan, then book. One warning (transfer not reversible).
- The gold "ticket" card shows the cpp in the perforated stub, and the dashed route line connects the steps.
- Alternatives include Virgin Atlantic (104,000 · 2.91¢), Flying Blue (117,000 · 2.73¢), United (141,000 · 2.40¢), KrisFlyer, and the Chase portal (~275,000 pts · 1.25¢) near the bottom — the portal must **not** win.
- Dashboard afterwards: totals update, donut shows the two programs, "Recent playbooks" lists this run with its cpp.

## Scenario B — split-source funding

**Set balances to exactly:** Chase `40000`, Amex Membership Rewards `30000` (remove/edit others).
**Playbook:** JFK → SIN, departure `2026-11-05`, Economy, 1 passenger.

Expected:
- Best route: **Chase + Amex → Singapore Airlines KrisFlyer — 48,000 pts total, 2.68¢/pt**: transfer from Chase and top up from Amex into KrisFlyer, then book. Two warnings (both transfers irreversible).
- The stub shows the per-program points breakdown across both currencies, plus the cash-out floor line ("Same points as cash/credits: $X — this route captures N× that").
- This proves no single balance covered the award and the engine combined sources correctly.

## Scenario C — two-hop chain discovery

**Set balances to exactly:** Chase `300000` only.
**Playbook:** JFK → NRT, departure `2026-10-14`, Business, 1 passenger.

Expected:
- Best route: same Aeroplan one-hop as Scenario A (it's the best value).
- Expand the alternatives: the list must include **Chase Ultimate Rewards → Marriott Bonvoy → Alaska Airlines Atmos Rewards — 225,000 pts, 1.50¢/pt** with three warnings (two irreversible transfers + a "this hop loses points" flag from the 3:1 ratio). Its transfer step notes the "+5,000 bonus per 60,000 transferred" block bonus.
- This is the honest behavior we want: the engine *finds* the exotic chain, ranks it truthfully below better options, and explains why.

## Scenario D — hotel playbook (new)

**Set balances to exactly:** Chase `120000`, Amex `80000`.
**Playbook page:** switch the toggle to **Hotel**. City code `TYO` (name "Tokyo"), check-in `2026-10-14`, check-out `2026-10-17`, 1 room, 2 guests.

Expected:
- Best route: **Chase Ultimate Rewards → World of Hyatt — 63,000 pts, 2.26¢/pt**: transfer 63,000 Chase → Hyatt, then book "a Category 6 Hyatt in Tokyo · 3 nights". No taxes line (award nights are generally tax-free; we don't guess resort fees).
- The stub shows the floor comparison: those 63,000 Chase points are worth $630 as cash, and this stay captures **2.3×** that.
- Alternatives include Hilton (via Amex 1:2), IHG (via Chase), Marriott, and the Chase portal — the portal must **not** win.
- Verify all of this without the browser: `npx tsx scripts/scenario-check.ts` runs Scenarios A–D and asserts the split-source, two-hop, Hyatt-path, and floor invariants.

## Other checks

- **Free-tier gate:** set `PLAYBOOK_FREE_LIMIT=1`, restart, run one playbook, run another → the second must be refused with the upgrade message. Restore to 999.
- **Hourly rate limit:** everyone (including premium) is capped at 10 playbooks/hour; the 11th returns a friendly 429. This protects provider quota.
- **Health endpoint:** `curl localhost:3000/api/health` → `{ ok: true, checks: { database: true, awardProvider: "mock", ... } }`. Point UptimeRobot at this in production.
- **Date validation:** a past departure date or a check-out before check-in must return a clear 400, not a crash.
- **Cache:** run the same query twice; the second response is near-instant (shared `award_cache`, 6h TTL). Different dates re-query the provider.
- **Validation:** origin "JF" or a past-malformed date must return a clear 400 error message, not a crash.
- **No balances:** delete all balances, run any playbook → friendly "none of it is reachable with your current balances" message.
- **Mobile:** at ~375px width, the nav collapses to the menu button, forms stack to one column, the ticket card stays readable.
- **Signed-out access:** /dashboard redirects to /login; the landing page and its buttons all work signed-out.

## Known limits in mock mode

Mock miles and cash fares are *directionally* realistic (distance-based, deterministic) but not market data — don't judge sweet-spot accuracy until `AWARD_PROVIDER=seatsaero` is live. Award routings may show odd connecting airports; that's cosmetic mock data. Scenario A's 20,000 Marriott balance goes unused by design: partial balances are only applied at the award's own program (documented simplification in ARCHITECTURE.md).
